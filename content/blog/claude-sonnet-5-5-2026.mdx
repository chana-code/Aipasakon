วันที่ 28 กันยายน 2026 Anthropic ปล่อย Claude Sonnet 5.5 รุ่นใหม่ของโมเดลระดับกลางในตระกูล Claude จุดขายรอบนี้ไม่ใช่ความฉลาดที่เพิ่มขึ้นอย่างเดียว แต่เป็นความเร็วกับราคา Anthropic บอกว่ามันเร็วกว่า Sonnet 5 รุ่นก่อนหน้ามากกว่า 30% และต้นทุนต่องานถูกลงได้ถึง 30% สำหรับงานส่วนใหญ่ ขณะที่คะแนนในหลายการทดสอบขึ้นมาใกล้ Opus 5.5 ซึ่งเป็นรุ่นท็อปที่แพงกว่า

บทความนี้สรุปว่า Sonnet 5.5 คืออะไร ตัวเลขที่ Anthropic ประกาศบอกอะไรและไม่ได้บอกอะไร และสำหรับคนที่ใช้ Claude ทำงานทุกวัน มันเปลี่ยนอะไรบ้าง

## Sonnet คืออะไรในตระกูล Claude

Anthropic ทำโมเดลออกมาเป็นสามขนาด ชื่อเรียงจากใหญ่ไปเล็กคือ Opus, Sonnet และ Haiku ลองนึกภาพร้านที่มีพนักงานสามระดับ Opus คือผู้เชี่ยวชาญอาวุโส คิดลึกที่สุดแต่ค่าตัวแพงและทำงานช้ากว่า Haiku คือพนักงานที่ไวและถูก เหมาะกับงานซ้ำ ๆ ง่าย ๆ ส่วน Sonnet อยู่ตรงกลาง เป็นคนที่คุณเรียกใช้บ่อยที่สุด เพราะเก่งพอสำหรับงานส่วนใหญ่และไม่แพงจนต้องคิดทุกครั้งที่ใช้

เปรียบเทียบนี้ใช้ได้แค่เรื่องการแบ่งหน้าที่ ส่วนที่ไม่เหมือนคือโมเดลไม่ได้ทำงานได้ดีกว่ากันแบบเรียงชั้นทุกเรื่อง บางงาน Sonnet ทำได้ดีกว่า Opus ด้วยซ้ำ ซึ่งรอบนี้ก็มีตัวอย่างแบบนั้น

Sonnet 5 รุ่นก่อนหน้าเปิดตัวเมื่อราวสามเดือนก่อน Sonnet 5.5 จึงเป็นการอัปเกรดรอบสั้น และ Anthropic บอกว่า Haiku 5.5 จะตามมาในอีกไม่กี่สัปดาห์ โดยยังไม่ให้วันที่แน่นอน

## มันเก่งเรื่องอะไร

Anthropic เขียนไว้ตรง ๆ ว่า Sonnet 5.5 เก่งที่สุดกับงานประจำวันที่ขอบเขตชัด การแก้บั๊กในโค้ด และการทำเอกสาร สไลด์ และสเปรดชีตให้ออกมาเรียบร้อย พูดง่าย ๆ คืองานแบบที่คนทำงานออฟฟิศสั่ง AI อยู่ทุกวัน ไม่ใช่งานวิจัยยาวหลายวัน

อีกเรื่องที่ Anthropic ใส่มาในประกาศเพื่อให้เห็นภาพ คือมันเป็น Sonnet รุ่นแรกที่เล่นเกม Pokémon Red จบได้ โดยดูแค่ภาพหน้าจออย่างเดียว เหมือนคนนั่งดูจอแล้วกดปุ่มเอง เกมแบบนี้ต้องเล่นต่อเนื่องยาว ต้องจำว่าทำอะไรไปแล้วและวางแผนก้าวต่อไปเอง ซึ่งคล้ายกับสิ่งที่ AI ต้องทำตอนรับงานยาว ๆ ไปทำแทนคน

## ตัวเลขที่ประกาศ อ่านยังไงดี

Anthropic เผยผลทดสอบเทียบสามรุ่น คือ Sonnet 5.5, Sonnet 5 และ Opus 5.5 ตัวเลขทั้งหมดนี้มาจาก Anthropic เอง ยังไม่ใช่ผลทดสอบอิสระ

| การทดสอบ | วัดอะไร | Sonnet 5.5 | Sonnet 5 | Opus 5.5 |
|---|---|---|---|---|
| Terminal-Bench 4.0 | ให้ AI ทำงานเขียนโค้ดเองในหน้าต่างคำสั่ง | 70.6% | 10.3% | 66.4% |
| OSWorld 2.1 | ให้ AI ใช้คอมพิวเตอร์ทำงานแทนคน | 80.1% | 57.0% | 81.8% |
| GDPval-AA v2.1 | งานแบบที่คนทำงานวิชาชีพทำจริง | 1844 | 1449 | 1846 |
| Humanity's Last Exam (ใช้เครื่องมือได้) | คำถามยากระดับผู้เชี่ยวชาญ | 64.5% | 54.9% | 67.7% |
| FrontierCode 1.1 | โจทย์เขียนโค้ดยาก | 46.2% | 42.4% | 54.4% |

สิ่งที่ตารางนี้บอกมีสองเรื่อง

เรื่องแรก ในงานที่ใกล้กับงานออฟฟิศจริง อย่าง GDPval-AA กับการใช้คอมพิวเตอร์แทนคน Sonnet 5.5 ได้คะแนนแทบเท่า Opus 5.5 และในงานเขียนโค้ดผ่านหน้าต่างคำสั่ง มันได้คะแนนสูงกว่า Opus 5.5 ด้วยซ้ำ TechCrunch ตั้งข้อสังเกตว่าส่วนหนึ่งอาจเป็นเพราะมันถูกพอที่จะแตก agent ย่อยออกไปช่วยกันทำงานได้หลายตัวโดยไม่ชนเพดานงบ

เรื่องที่สอง ในงานที่ยากสุดจริง ๆ อย่างโจทย์โค้ดระดับสูงและคำถามระดับผู้เชี่ยวชาญ Opus 5.5 ยังนำอยู่ชัดเจน รุ่นท็อปจึงยังมีที่ทางของมัน

ตัวเลข Terminal-Bench ที่กระโดดจาก 10.3% เป็น 70.6% ดูน่าตื่นเต้น แต่ควรอ่านอย่างระวัง การทดสอบเวอร์ชันใหม่ ๆ มักตั้งใจให้ยากจนรุ่นเก่าทำคะแนนได้ต่ำ การกระโดดขนาดนี้จึงบอกว่ารุ่นใหม่ผ่านจุดที่รุ่นเก่าติดได้ ไม่ได้แปลว่ามันเก่งขึ้นเจ็ดเท่าในงานทั่วไป และ Anthropic เองก็เขียนไว้ในประกาศว่าไม่มีชุดทดสอบไหนจับความผิดพลาดได้ครบทุกแบบ

ตัวเลขที่ใกล้ชีวิตจริงกว่าคือคำบอกเล่าจากบริษัทที่ได้ลองก่อน เช่น Zendesk บอกว่าจัดการตั๋วร้องเรียนของลูกค้าได้เร็วขึ้น 20% และ Box บอกว่าแม่นขึ้น เร็วขึ้น 2.4 เท่า และใช้ token น้อยลง 12% ข้อควรจำคือบริษัทที่ถูกยกมาในประกาศมักเป็นเคสที่ผลออกมาดี

## ถูกลงยังไง ในเมื่อราคาเท่าเดิม

ราคาต่อหน่วยของ Sonnet 5.5 เท่ากับ Sonnet 5 ทุกอย่าง คือ 2 ดอลลาร์ต่อ 1 ล้าน token ขาเข้า และ 10 ดอลลาร์ต่อ 1 ล้าน token ขาออก token คือหน่วยนับข้อความที่ AI อ่านและเขียน คิดคร่าว ๆ ว่าเป็นชิ้นส่วนของคำ

แล้วต้นทุนลดลงได้ยังไง คำตอบคือมันใช้ token น้อยลงต่องาน ลองนึกถึงช่างสองคนที่คิดค่าแรงรายชั่วโมงเท่ากัน คนหนึ่งทำงานเดียวกันเสร็จเร็วกว่า บิลสุดท้ายก็ถูกกว่า ทั้งที่ค่าแรงต่อชั่วโมงไม่ได้ลด Sonnet 5.5 คิดและเขียนออกมาน้อยลงเพื่อให้ได้งานเท่าเดิม Anthropic ยกตัวอย่างว่าในการทดสอบงานความรู้ระยะยาวชุดหนึ่ง Sonnet 5.5 ที่ตั้งระดับความพยายามปานกลาง ทำคะแนนได้ดีกว่าคะแนนที่ดีที่สุดของ Sonnet 5 ด้วยต้นทุนราวหนึ่งในเก้าต่องาน

สำหรับคนที่ใช้ Claude ผ่านแอปแบบจ่ายรายเดือน ค่าบริการของคุณไม่ได้เปลี่ยน สิ่งที่คุณจะรู้สึกได้ชัดที่สุดคือคำตอบที่มาเร็วขึ้น ส่วนสำหรับธุรกิจที่เรียกใช้ Claude ผ่าน API ต้นทุนต่องานที่ลดลงคือเงินที่ลดลงจริง

## ระดับความพยายาม ปุ่มที่ควรรู้จัก

Sonnet 5.5 ให้เลือกได้ว่าจะให้มันคิดนานแค่ไหนก่อนตอบ ที่เรียกว่า effort ตั้งต่ำ มันตอบเร็วและใช้ token น้อย เหมาะกับงานประจำ ตั้งสูง มันคิดนานขึ้นและตรวจงานละเอียดขึ้น เหมาะกับงานที่ผิดไม่ได้

Anthropic ตั้งค่าเริ่มต้นไว้ที่ระดับปานกลางในแอป Claude และ Claude Code ส่วนฝั่ง API สำหรับนักพัฒนาตั้งไว้ที่ระดับสูง ถ้าวันหนึ่งคุณรู้สึกว่าคำตอบในแอปเร็วแต่ตื้นเกินไปสำหรับงานสำคัญ ให้รู้ไว้ว่านี่คือตัวแปรที่ปรับได้ ไม่ใช่เพดานของโมเดล

## เรื่องความปลอดภัยที่เปลี่ยนไป

Anthropic บอกว่า Sonnet 5.5 มีความสามารถด้านความปลอดภัยไซเบอร์สูงขึ้นจนใกล้เคียงรุ่นท็อป จึงเป็น Sonnet รุ่นแรกที่ต้องใช้มาตรการป้องกันด้านไซเบอร์แบบเดียวกับรุ่นใหญ่ คำขอที่ระบบประเมินว่าเสี่ยงสูงจะถูกส่งไปให้ Sonnet 5 รุ่นเก่าตอบแทน ส่วนคนที่ทำงานป้องกันระบบจริง ๆ สมัครเข้าโครงการยืนยันตัวตนเพื่อขอสิทธิ์เพิ่มได้

สำหรับคนทำงานทั่วไป เรื่องนี้แทบไม่กระทบ แต่ถ้าคุณทำงานด้าน IT หรือความปลอดภัย แล้ววันหนึ่งเจอว่าคำตอบเรื่องช่องโหว่ดูระวังตัวผิดปกติ นี่คือเหตุผล

## ใช้ได้ที่ไหน

Sonnet 5.5 ใช้ได้แล้วในแอป Claude และ Claude Code และสำหรับนักพัฒนา เรียกใช้ได้ผ่าน Claude Platform ของ Anthropic เอง รวมถึง AWS, Google Cloud และ Microsoft ชื่อโมเดลสำหรับเรียกผ่าน API คือ claude-sonnet-5-5

## แล้วมันเปลี่ยนอะไรสำหรับคุณ

ถ้าคุณใช้ Claude ทำงานทุกวัน ร่างอีเมล สรุปเอกสาร ทำสไลด์ หรือให้ agent อย่าง Claude Code ช่วยสร้างเว็บเล็ก ๆ สิ่งที่ควรลองมีสามอย่าง

1. **ลองงานประจำของคุณกับรุ่นใหม่** เอางานที่คุณทำซ้ำทุกสัปดาห์ เช่น สรุปรายงานประชุม หรือทำตารางสรุปยอดขาย ให้ Sonnet 5.5 ทำ แล้วเทียบกับผลเดิมด้วยตาคุณเอง ตัวเลขในตารางข้างบนเป็นค่าเฉลี่ยของงานที่ไม่ใช่งานของคุณ งานของคุณเท่านั้นที่บอกได้จริงว่ามันดีขึ้นแค่ไหน
2. **ไม่ต้องเลือก Opus ทุกครั้ง** ถ้าที่ผ่านมาคุณเลือกรุ่นท็อปเป็นค่าเริ่มต้นเพื่อความชัวร์ รอบนี้งานประจำส่วนใหญ่ใช้ Sonnet 5.5 ได้ใกล้เคียงกันและเร็วกว่า เก็บ Opus ไว้ให้งานที่ยากจริง เช่น วิเคราะห์ที่ต้องคิดหลายชั้น หรือโค้ดที่ซับซ้อน
3. **ยังตรวจงานเหมือนเดิม** โมเดลที่เร็วขึ้นไม่ได้แปลว่าผิดน้อยลงในทุกเรื่อง การตรวจสิ่งที่ AI ส่งมายังเป็นหน้าที่ของคุณเสมอ

ภาพใหญ่ของข่าวนี้คือช่องว่างระหว่างโมเดลระดับกลางกับรุ่นท็อปแคบลงเรื่อย ๆ งานที่ปีก่อนต้องใช้รุ่นแพงที่สุด วันนี้รุ่นกลางทำได้ใกล้เคียงในราคาที่ถูกกว่า สำหรับธุรกิจขนาดเล็ก นี่แปลว่าต้นทุนของการเอา AI มาทำงานจริงลดลงอีกขั้น
