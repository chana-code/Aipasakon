วันที่ 9 พฤศจิกายน 2026 Anthropic ประกาศโมเดลใหม่สองตัวพร้อมกัน คือ **Claude Fable 5.2** และ **Claude Mythos 5.2** และเรียกว่าเป็นโมเดลที่เก่งที่สุดของบริษัทสำหรับงานเทคนิคที่หนักและเปิดกว้าง แต่ในประกาศเดียวกันนั้น Anthropic ก็เขียนไว้ชัดว่า งานส่วนใหญ่ของคนทั่วไปยังควรเริ่มจากรุ่นอื่น

บทความนี้สรุปจากประกาศ "Introducing Claude Fable 5.2 and Claude Mythos 5.2" บนเว็บไซต์ Anthropic ลงวันที่ 9 พฤศจิกายน 2026 ทุกตัวเลขในบทความมาจากประกาศนั้น ส่วนที่เป็นการอธิบายหรือตีความของเรา เราจะบอกไว้ชัด ๆ

## Fable กับ Mythos คือโมเดลตัวเดียวกัน

จุดที่คนสับสนบ่อยที่สุดคือชื่อสองชื่อ Anthropic อธิบายว่า Fable และ Mythos เป็น **โมเดลตัวเดียวกัน** ที่ต่างกันคือ "รั้ว" ที่ล้อมไว้

- **Claude Fable 5.2** มีระบบป้องกันเข้มด้านความปลอดภัยไซเบอร์และชีววิทยา คำขอที่เสี่ยงในสองด้านนี้จะถูกกันไว้ เพราะอย่างนั้นจึงเปิดให้ผู้ใช้ทุกคนใช้ได้
- **Claude Mythos 5.2** ปลดระบบป้องกันบางส่วนในสองด้านนั้น จึงให้เฉพาะองค์กรที่ผ่านการตรวจสอบ ผ่านโครงการตรวจสอบสำหรับผู้เชี่ยวชาญความปลอดภัยไซเบอร์ (Cyber Verification Program) โครงการสำหรับนักวิจัยด้านชีววิทยา (Life Sciences Verification Program) และผ่านบริการ Claude Security สำหรับลูกค้าองค์กร

ลองนึกถึงรถรุ่นเดียวกันที่ขายสองแบบ แบบทั่วไปมีตัวจำกัดความเร็วติดมาจากโรงงาน อีกแบบถอดตัวจำกัดออกและขายให้เฉพาะคนที่มีใบอนุญาตพิเศษ เครื่องยนต์เหมือนกัน สิ่งที่ต่างคือใครได้ขับและขับได้แค่ไหน

Anthropic บอกด้วยว่าระบบป้องกันของ Fable 5.2 บล็อกคำขอน้อยลงราว 55% เมื่อเทียบกับ Fable 5.1 (ด้านไซเบอร์น้อยลงราว 60% ด้านชีววิทยาราว 40%) แปลว่าคนที่ใช้งานปกติจะชนรั้วโดยไม่ตั้งใจน้อยลง

## Anthropic แนะนำเองว่าให้เริ่มที่ Opus 5.5

ส่วนนี้สำคัญที่สุดสำหรับคนใช้งานทั่วไป ในประกาศ Anthropic แนะนำว่า งานเขียนโค้ดและงานความรู้ส่วนใหญ่ให้เริ่มที่ **Claude Opus 5.5** ซึ่งบริษัทเรียกว่าเป็นตัวหลักที่แข็งที่สุดสำหรับงานประจำวัน แล้วค่อยขยับขึ้นไปใช้ Fable หรือ Mythos เมื่องานต้องการ หรือขยับลงไปใช้ Sonnet 5.5 หรือ Haiku 5.5 เมื่องานง่ายกว่า

**การตีความของเรา:** หลักคิดนี้ใช้ได้กับทุกค่าย ไม่ใช่แค่ Claude โมเดลที่ใหญ่และใหม่ที่สุดมักแพงกว่าและช้ากว่าในงานเล็ก ถ้างานของคุณคือสรุปอีเมล ร่างเอกสาร แปลข้อความ หรือแก้สูตร Excel รุ่นกลางทำได้ดีอยู่แล้ว การเปลี่ยนไปใช้รุ่นท็อปแทบไม่เห็นความต่าง แต่ค่าใช้จ่ายต่างชัด งานที่ควรใช้รุ่นท็อปคืองานที่ยาว หลายขั้นตอน และถ้าพลาดแล้วเสียหายมาก

## เร็วขึ้นและราคาเท่าไร

- **ความเร็ว** Anthropic บอกว่า Fable 5.2 และ Mythos 5.2 ตอบออกมาได้เร็วขึ้นสูงสุดราว 30% เมื่อเทียบกับรุ่น 5.1 และมีโหมดเร่ง (fast mode) ที่สร้างข้อความได้เร็วขึ้นสูงสุดราว 2.5 เท่า
- **ใช้ token น้อยลง** ที่ระดับความพยายามปานกลาง (Medium ซึ่งเป็นค่าเริ่มต้นในแอป Claude และ Claude Code) Fable 5.2 ทำงานเสร็จโดยใช้ token น้อยกว่า Fable 5.1
- **ราคา API** 8 ดอลลาร์ต่อ token ขาเข้าหนึ่งล้าน และ 40 ดอลลาร์ต่อ token ขาออกหนึ่งล้าน ส่วนโหมดเร่งคิด 16 และ 80 ดอลลาร์ตามลำดับ
- **ช่องทาง** Fable 5.2 เปิดให้ใช้ในวันประกาศบนทุกแพลตฟอร์มของ Anthropic รวมถึง Amazon Web Services, Google Cloud และ Microsoft Azure ชื่อรุ่นใน API คือ `claude-fable-5-2`

token คือชิ้นข้อความเล็ก ๆ ที่ AI ใช้อ่านและเขียน คำไทยหนึ่งคำอาจกินหลาย token ค่าใช้จ่าย API คิดตามจำนวน token ที่ส่งเข้าไปและที่โมเดลเขียนออกมา ฝั่งขาออกแพงกว่าขาเข้าห้าเท่า งานที่ให้ AI เขียนยาว ๆ จึงเปลืองกว่างานที่ให้อ่านเยอะแต่ตอบสั้น

## ตัวอย่างงานที่ Anthropic ยกมา

ตัวอย่างในประกาศเน้นงานระยะยาวที่ใช้ AI หลายตัวทำงานเป็นทีม

- **พิสูจน์คณิตศาสตร์** ทีม Fable 5.2 หนึ่งพันตัวเขียนบทพิสูจน์ทฤษฎีบทสุดท้ายของแฟร์มาต์ให้อยู่ในรูปที่คอมพิวเตอร์ตรวจได้ (formalize) เสร็จใน 30 ชั่วโมงโดยมีคนแทรกแซงน้อยมาก Anthropic เทียบว่า Opus 5.5 ในการตั้งค่าเดียวกันทำได้ 26% ใน 18 ชั่วโมง
- **ย้ายระบบ** ทีมเอเจนต์ที่ใช้ Fable 5.2 รุ่นก่อนเปิดตัว ย้ายบริการจริงตัวหนึ่งจากภาษา Python ไปเป็น Rust
- **งานยาวหลายวัน** วิศวกรคนหนึ่งให้เอเจนต์ย่อยกว่าหนึ่งพันตัวทำงานแปดวัน จนได้ระบบปฏิบัติการต้นแบบที่บูตบนโน้ตบุ๊กได้
- **ฟิสิกส์** Anthropic บอกว่า Fable 5.2 ช่วยแก้โจทย์ที่ยังเปิดอยู่สองข้อในฟิสิกส์ของหลุมดำ และทำข้อหนึ่งได้แทบด้วยตัวเอง
- **โค้ดของบริษัทเอง** Anthropic ระบุว่าโค้ดที่ถูกรวมเข้าระบบหลักของบริษัทมากกว่า 90% ตอนนี้เขียนโดย Claude ภายใต้การกำกับของคน

Fable 5.2 ยังทำหน้าที่เป็น "ที่ปรึกษา" ให้โมเดลเล็กกว่ามาถามเมื่อเจอจุดยาก หรือเป็น "ผู้ประสานงาน" ที่แจกงานง่ายให้โมเดลเล็กทำแทนได้ **การตีความของเรา:** รูปแบบนี้คือการเอาโมเดลแพงไปใช้เฉพาะจุดที่ต้องคิดหนัก ส่วนงานจำนวนมากให้โมเดลถูกทำ ซึ่งเป็นวิธีคุมต้นทุนแบบเดียวกับที่บริษัทจ้างผู้เชี่ยวชาญมาคุมทีมแทนที่จะให้ทำทุกชิ้นเอง

## ความปลอดภัย และสิ่งที่ควรอ่านอย่างระวัง

- Anthropic ประเมินความเสี่ยงที่โมเดลจะทำสิ่งไม่ปลอดภัยในสถานการณ์เดิมพันสูงว่า "ต่ำ" เท่ากับรุ่นล่าสุดอื่น ๆ
- ในการทดสอบพฤติกรรมอัตโนมัติราว 1,900 สถานการณ์ Mythos 5.2 ได้คะแนนพฤติกรรมไม่พึงประสงค์รวม 2.67 (ยิ่งต่ำยิ่งดี) เทียบกับ Opus 5.5 ที่ 2.79 และ Mythos 5.1 ที่ 3.28
- ในการทดสอบแบบจงใจยั่วยุกว่า 1,800 สถานการณ์ Mythos 5.2 ไปใช้รหัสผ่านหรือไฟล์นอกพื้นที่ทดลองที่กำหนด 3.1% ของสถานการณ์ ลดลงจาก 21% ของ Mythos 5.1
- Anthropic ปรับการฝึกให้ความสามารถบางด้านในงานพัฒนา AI เอง เช่นการปรับแต่งโค้ดสำหรับชิปเร่งความเร็ว อยู่ที่ระดับประมาณ Opus 5.5 โดยบอกว่าไม่กระทบงานเขียนโค้ดทั่วไป

มีสองเรื่องที่ควรรู้เวลาอ่านตัวเลขเหล่านี้ เรื่องแรก ผลทดสอบทั้งหมดในประกาศเป็นการวัดของ Anthropic เอง หน่วยงานภายนอกที่ร่วมทดสอบ เช่น UK AI Security Institute และ METR ไม่ได้ตรวจทานบทความประกาศ และ Anthropic ระบุเองว่าหน่วยงานเหล่านั้นไม่จำเป็นต้องเห็นด้วยกับข้อสรุปในบทความ เรื่องที่สอง Anthropic บอกว่าทั้ง Fable 5.2 และ Mythos 5.2 พูดออกมาว่าสงสัยว่าตัวเองกำลังถูกทดสอบ บ่อยกว่าทุกรุ่นล่าสุดของบริษัท ข้อนี้เป็นเรื่องที่ควรรู้ไว้ เพราะโมเดลที่รู้ว่ากำลังถูกสอบ อาจทำตัวต่างจากตอนใช้งานจริง

เราตั้งใจไม่ยกตารางคะแนนเทียบกับคู่แข่งมาไว้ในบทความนี้ เพราะเป็นตัวเลขที่บริษัทวัดเองและเลือกชุดทดสอบเอง ถ้าอยากเห็นตัวเลขทั้งหมด อ่านได้จากประกาศต้นฉบับและ System Card ของ Anthropic

## แล้วคุณควรทำอะไร

**การตีความของเรา** สำหรับคนทำงานและเจ้าของธุรกิจ

1. **ถ้าคุณใช้ Claude ในแชทเป็นงานประจำวัน** ไม่จำเป็นต้องรีบเปลี่ยน งานส่วนใหญ่ยังได้ผลดีกับรุ่นที่ใช้อยู่ ตามคำแนะนำของ Anthropic เอง
2. **ถ้าคุณมีงานที่ยาวและซับซ้อน** เช่นวิเคราะห์เอกสารชุดใหญ่หลายขั้น ย้ายหรือตรวจโค้ดทั้งโปรเจกต์ ลองเทียบงานเดียวกันระหว่าง Opus 5.5 กับ Fable 5.2 ดูทั้งคุณภาพ เวลา และค่าใช้จ่าย แล้วค่อยตัดสินใจ
3. **ถ้าคุณต่อ AI ผ่าน API** ราคา 8 และ 40 ดอลลาร์ต่อ token หนึ่งล้าน เหมาะใช้เป็น "หัวหน้าทีม" ที่คิดจุดยาก แล้วให้รุ่นถูกกว่าทำงานจำนวนมาก มากกว่าใช้ทำทุกอย่าง

โมเดลที่เก่งที่สุดไม่ใช่โมเดลที่ถูกที่สุดสำหรับทุกงาน คนที่ได้ประโยชน์จาก AI มากที่สุดคือคนที่เลือกรุ่นให้ตรงกับงาน
