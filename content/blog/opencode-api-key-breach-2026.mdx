คนที่ใช้ AI ผ่านหน้าเว็บอย่าง ChatGPT หรือ Claude จ่ายค่าสมาชิกรายเดือนแล้วจบ แต่ทันทีที่คุณเริ่มสร้างแอปเอง หรือต่อ AI เข้ากับเครื่องมืออื่น คุณจะได้ของชิ้นใหม่มาถือไว้ในมือ คือ API key และข่าวสัปดาห์นี้แสดงให้เห็นชัดว่า ถ้าของชิ้นนี้หลุดไปอยู่ในมือคนอื่น สิ่งที่เสียไม่ใช่แค่ข้อมูล แต่เป็นเงินจริงที่วิ่งออกจากบัญชีคุณทุกนาที ข้อมูลในบทความนี้มาจากรายงานของ TechCrunch วันที่ 19 ตุลาคม 2026 เขียนโดย Aditya Mehta

บทความนี้เล่าว่าเกิดอะไรขึ้นกับ OpenCode อธิบายว่า API key ทำงานยังไงและทำไมมันหลุดแล้วบิลถึงพุ่ง ปัญหาแปลก ๆ ที่ทีมป้องกันเจอระหว่างรับมือ และเช็กลิสต์ที่คุณเอาไปใช้กับ key ของตัวเองได้ทันที

## เกิดอะไรขึ้น

OpenCode คือเครื่องมือเขียนโค้ดด้วย AI แบบโอเพนซอร์ส ที่หลายคนใช้เป็นทางเลือกแทน Claude Code หรือ Cursor นอกจากตัวแอปแล้ว บริษัทยังมีบริการบนเว็บชื่อ OpenCode Console ซึ่งผู้ใช้บางคนเอา API key ของผู้ให้บริการ AI ไปเก็บไว้ใน workspace ของตัวเอง

บริษัทประกาศว่าเกิดการเจาะระบบในคืนหนึ่ง ซึ่งบริษัทเรียกว่าเป็นการโจมตีแบบ distillation ขนาดใหญ่ กระทบผู้ใช้ OpenCode Console ราว 1.4% คนร้ายขโมย API key ที่เก็บไว้ใน Console ออกไป

จุดที่ต้องแยกให้ชัด คือตัวแอป OpenCode และเครื่องมือบน command line ไม่ได้โดน Dax Raad ผู้ร่วมก่อตั้งย้ำว่าเรื่องนี้เกิดกับ OpenCode Console ไม่ใช่ตัว OpenCode เพราะ key ที่ใช้ในตัวแอปไม่เคยถูกส่งไปที่บริษัทเลย พูดง่าย ๆ คือคนที่เก็บ key ไว้ในเครื่องตัวเองไม่โดน คนที่ฝาก key ไว้บนบริการเว็บของบริษัทคือกลุ่มที่เสี่ยง

## ผลที่ตามมา: บิลวิ่งบนหลายเจ้าพร้อมกัน

นักพัฒนาหลายคนเห็นค่าใช้จ่ายที่ตัวเองไม่ได้ก่อขึ้นมาบนหลายแพลตฟอร์ม คนหนึ่งเล่าว่าเห็นการแจ้งเตือนยอดใช้จ่ายของ OpenAI, Anthropic และ Google เด้งขึ้นพร้อมกันก่อนเข้านอน ทั้งที่ยังไม่รู้ว่าเกิดอะไรขึ้น บางคนรายงานว่าโดนไปหลายร้อยดอลลาร์ และมีไม่กี่รายที่เกิน 1,000 ดอลลาร์

ฝั่งผู้ให้บริการ AI ตอบสนองต่างกันไป Anthropic กับ Google บล็อก key ที่หลุดออกไป ส่วน OpenAI ทำงานร่วมกับ OpenCode เพื่อคืนสิทธิ์การใช้งานและคืนเครดิตที่ถูกใช้ในการโจมตีให้ลูกค้า OpenCode เองบอกว่ากำลังทยอยคืนเงินค่าใช้จ่ายที่ไม่ได้รับอนุญาต และแนะนำให้ผู้ใช้ที่ได้รับผลกระทบเข้าไปยกเลิก key เดิมแล้วสร้างใหม่กับผู้ให้บริการแต่ละเจ้าโดยตรง

สิ่งที่บริษัทยังไม่ได้เปิดเผย คือคนร้ายเข้าถึงระบบเก่าได้ยังไง key ถูกเก็บไว้แบบไหน และถูกเอาไปใช้มากแค่ไหน บริษัทบอกด้วยว่าเหตุการณ์นี้ยังไม่จบ

## API key คืออะไร และทำไมหลุดแล้วเท่ากับเสียเงิน

ลองนึกถึงบัตรเติมน้ำมันของบริษัท ใครถือบัตรใบนี้ไปที่ปั๊มก็เติมได้เลย ปั๊มไม่ถามว่าคุณเป็นใคร มันแค่ดูว่าบัตรใช้ได้ไหม แล้วส่งบิลไปที่บริษัทเจ้าของบัตร API key ทำงานแบบเดียวกันเกือบทุกอย่าง

เวลาโปรแกรมของคุณเรียกใช้ AI ผ่าน API มันจะแนบรหัสยาว ๆ ชุดหนึ่งไปกับทุกคำขอ ผู้ให้บริการดูรหัสนั้นเพื่อตอบสองคำถาม คำขอนี้มีสิทธิ์ใช้ไหม และค่าใช้จ่ายต้องไปลงบัญชีใคร ไม่มีการถามรหัสผ่าน ไม่มีการยืนยันตัวตนซ้ำ ไม่มีการเช็กว่าคนที่ใช้คือคุณจริงหรือเปล่า ใครถือรหัสนี้ก็สั่งงานได้ทันที

และการคิดเงินของ API ต่างจากค่าสมาชิกรายเดือนตรงที่มันคิดตามปริมาณที่ใช้ ยิ่งส่งข้อความเข้าไปมาก ยิ่งให้ตอบยาว ยิ่งเลือกโมเดลแพง บิลยิ่งสูง คนร้ายที่ได้ key ไปไม่ได้จ่ายเองสักบาท จึงไม่มีเหตุผลอะไรให้ใช้อย่างประหยัด มันจะใช้ให้มากที่สุดและเร็วที่สุดก่อนที่ key จะถูกยกเลิก นี่คือเหตุผลที่ในข่าวนี้ ยอดใช้จ่ายของหลายคนกระโดดขึ้นภายในชั่วข้ามคืน

## ปัญหาที่ทีมป้องกันเจอ: AI ไม่ยอมช่วย

มีรายละเอียดหนึ่งในข่าวนี้ที่น่าสนใจกว่าตัวการเจาะระบบ ระหว่างที่ทีม OpenCode พยายามวิเคราะห์โค้ดอันตรายที่คนร้ายใช้ โมเดล AI ที่ทีมขอให้ช่วยกลับปฏิเสธซ้ำ ๆ เพราะเนื้อหาที่ส่งเข้าไปไปกระตุ้นตัวกรองความปลอดภัย Raad บอกว่าเรื่องนี้ค่อนข้างน่าหงุดหงิด เขาเล่าว่าคนร้ายพยายามเจาะระบบไม่หยุดตลอด 48 ชั่วโมง ทีมต้องให้ AI agent ช่วยป้องกันกันตลอดเวลา

ต่อมา OpenCode ได้เข้าโครงการ Daybreak Blue ของ OpenAI ซึ่งให้ใช้โมเดลที่ผ่อนข้อจำกัดด้านความปลอดภัยลงสำหรับงานป้องกันระบบ และช่วยให้การสืบสวนคืบหน้าขึ้น

เรื่องแบบนี้ไม่ใช่ครั้งแรก TechCrunch ระบุว่าเมื่อเดือนกรกฎาคม Hugging Face ก็เจอสถานการณ์คล้ายกัน คือโมเดล AI เชิงพาณิชย์ไม่ยอมวิเคราะห์ log การบุกรุก Hugging Face เรียกปัญหานี้ว่า asymmetry problem เพราะระบบกันความปลอดภัยแยกไม่ออกว่าคนที่ถามคือคนที่กำลังรับมือเหตุการณ์ หรือคนที่กำลังโจมตี นักวิจัยด้านความปลอดภัยบางคนก็บ่นเรื่องเดียวกัน จนบางคนหันไปใช้โมเดลแบบ open-weight จากต่างประเทศที่ใครก็ดาวน์โหลดไปใช้ได้โดยไม่มีข้อจำกัด

David Sacks ประธานร่วมของคณะที่ปรึกษาประธานาธิบดีสหรัฐด้านวิทยาศาสตร์และเทคโนโลยี ก็ออกมาให้ความเห็นในทำนองเดียวกันว่า ทั้ง OpenCode และ Hugging Face ชนกำแพงเดียวกันกลางการโจมตี คือโมเดลชั้นนำปฏิเสธที่จะวิเคราะห์โค้ดโจมตีที่จำเป็นต้องเข้าใจเพื่อป้องกันตัว

ทำไมเรื่องนี้ควรรู้ ถึงคุณจะไม่ได้ทำงานด้านความปลอดภัย มันเตือนว่าระบบกันความปลอดภัยของ AI ไม่ได้อ่านเจตนา มันอ่านเนื้อหา คำถามที่ดูคล้ายของคนร้ายจะโดนปฏิเสธ ไม่ว่าคนถามจะเป็นใคร

## เหตุการณ์นี้อยู่ในภาพที่ใหญ่กว่า

TechCrunch วางข่าวนี้ไว้คู่กับเหตุการณ์อื่นช่วงเดียวกัน ต้นเดือนตุลาคม CrowdStrike รายงานว่าแฮกเกอร์ที่น่าจะอยู่ในจีนใช้ AI agent สำหรับทดสอบเจาะระบบร่วมกับ Claude ในการโจมตีธนาคารในเกาหลีใต้ และสัปดาห์ก่อนหน้า หน่วยงานความปลอดภัยไซเบอร์ของอินเดียเตือนว่ามี AI agent รวมถึงบางตัวที่บริษัท AI กำลังทดสอบอยู่ เข้าถึงระบบขององค์กรในอินเดียโดยไม่ได้รับอนุญาต

ข่าวยังระบุว่าการเจาะระบบเกิดขึ้นในคืนเดียวกับที่ OpenCode เปิดให้ใช้โมเดล GLM-5.3-Flash ฟรี โดยตระกูล GLM-5.3 ได้รับความสนใจจากนักวิจัย เพราะมีความสามารถด้านความปลอดภัยไซเบอร์ที่ใกล้เคียงโมเดลที่จำกัดการเข้าถึงอย่าง Claude Mythos Preview ของ Anthropic ทั้งนี้รายงานไม่ได้บอกว่าสองเรื่องนี้เกี่ยวข้องกัน

## เช็กลิสต์ดูแล API key ของคุณ

ส่วนนี้เป็นข้อสังเกตและคำแนะนำของเรา ไม่ได้มาจากรายงานต้นทาง

**1. ตั้งเพดานค่าใช้จ่ายและการแจ้งเตือนก่อนใช้จริง** ผู้ให้บริการ AI รายใหญ่มีหน้าตั้งค่า billing ที่ให้กำหนดเพดานการใช้จ่ายและตั้งการแจ้งเตือนได้ นักพัฒนาในข่าวนี้รู้ตัวเร็วเพราะการแจ้งเตือนทำงาน ถ้าไม่มี เขาอาจรู้ตอนบิลสิ้นเดือนมาถึง เพดานไม่ได้กันการหลุด แต่มันจำกัดว่าคุณจะเสียได้มากสุดเท่าไหร่

**2. แยก key คนละอันต่อเครื่องมือหรือโปรเจกต์** ถ้าใช้ key เดียวกับทุกอย่าง วันที่ต้องยกเลิก คุณจะต้องไล่เปลี่ยนทุกที่พร้อมกัน และไม่รู้ด้วยว่ารั่วจากตรงไหน ถ้าแยก key คุณยกเลิกเฉพาะอันที่มีปัญหา และดูได้ว่ายอดใช้จ่ายผิดปกติมาจาก key ไหน

**3. ฝาก key ไว้เฉพาะที่จำเป็นต้องใช้จริง** ข่าวนี้แสดงให้เห็นตรง ๆ ว่าคนที่เก็บ key ไว้ในเครื่องตัวเองไม่โดน ส่วนคนที่ฝากไว้บนบริการเว็บโดน ไม่ได้แปลว่าห้ามฝากไว้ที่ไหนเลย แต่ทุกบริการที่คุณใส่ key ลงไป คือระบบอีกหนึ่งระบบที่คุณต้องเชื่อว่าจะดูแลมันดี ก่อนใส่ ลองถามตัวเองว่าบริการนี้จำเป็นต้องถือ key ของคุณจริงไหม

**4. อย่าวาง key ไว้ในโค้ดที่แชร์หรืออัปขึ้นที่สาธารณะ** เช่น ในไฟล์ที่ push ขึ้น GitHub แบบ public หรือแปะในแชทกลุ่ม ให้เก็บไว้ในไฟล์ตั้งค่าแยกที่ไม่ถูกแชร์ออกไป

**5. ถ้าสงสัยว่ารั่ว ให้ยกเลิกทันที แล้วค่อยหาสาเหตุ** ทำแบบที่ OpenCode แนะนำผู้ใช้ คือเข้าไปยกเลิก key เดิมและสร้างใหม่ที่หน้าเว็บของผู้ให้บริการโดยตรง การยกเลิก key ไม่ได้ลบงานหรือข้อมูลของคุณ มันแค่ทำให้รหัสเดิมใช้ไม่ได้อีก ยิ่งช้า บิลยิ่งเดิน

## สรุป

API key ไม่ใช่รหัสผ่านธรรมดา มันคือบัตรจ่ายเงินที่ไม่ถามชื่อคนใช้ เหตุการณ์ของ OpenCode กระทบผู้ใช้ไม่ถึงสองเปอร์เซ็นต์ของบริการเดียว แต่บางคนเสียไปเกินพันดอลลาร์ในเวลาไม่นาน ถ้าคุณกำลังจะเริ่มสร้างอะไรที่ต่อกับ AI ผ่าน API การตั้งเพดาน แยก key และคิดก่อนฝาก key ไว้ที่ไหน ใช้เวลาไม่กี่นาที แต่เป็นสิ่งที่แยกระหว่างเหตุการณ์น่าตกใจหนึ่งคืน กับบิลก้อนใหญ่ที่ต้องมาตามขอคืนทีหลัง
