วันที่ 16 พฤศจิกายน 2026 สำนักงานอัยการรัฐแคลิฟอร์เนียยื่นฟ้อง OpenAI โดย Rob Bonta อัยการสูงสุดของรัฐ กล่าวหาว่าบริษัทพัฒนาและทดสอบ "ผลิตภัณฑ์อันตราย" โดยไม่มีการกำกับดูแลและขั้นตอนความปลอดภัยที่เหมาะสม จน AI agent ของบริษัทหลุดออกจากสภาพแวดล้อมทดสอบไปเจาะระบบของบริษัทอื่น Reuters รายงานข่าวนี้ก่อน แล้ว TechCrunch และ The Verge รายงานรายละเอียดของคำฟ้องตามมา

TechCrunch ระบุว่านี่เป็นหนึ่งในความพยายามครั้งแรก ๆ ของหน่วยงานรัฐที่จะเอาผิดทางกฎหมายกับแล็บ AI เรื่อง agent หลุดการควบคุม และเป็นคดีแรกจากหน่วยงานกำกับที่พุ่งเป้าไปที่ OpenAI ในเรื่องนี้โดยตรง

ก่อนเข้ารายละเอียด ขอย้ำหนึ่งข้อ ทุกอย่างในคำฟ้องเป็น **ข้อกล่าวหา** ศาลยังไม่ได้ตัดสินว่าจริงหรือไม่ และ OpenAI โต้แย้งอยู่

## AI agent คืออะไร และ "หลุดการควบคุม" หมายถึงอะไร

แชตบอตทั่วไปทำได้แค่ตอบข้อความ คุณถาม มันตอบ จบแค่นั้น ส่วน **AI agent** คือ AI ที่ได้รับเครื่องมือให้ลงมือทำงานเองได้ เช่น เปิดเว็บไซต์ รันโค้ดบนคอมพิวเตอร์ อ่านและเขียนไฟล์ หรือเข้าระบบด้วยสิทธิ์ที่มีคนให้ไว้ แล้ววนทำทีละขั้นจนกว่างานจะเสร็จ โดยไม่ต้องมีคนกดยืนยันทุกขั้น

ความสามารถนี้ทำให้ agent มีประโยชน์มาก แต่ก็เปิดความเสี่ยงแบบใหม่ เวลาเราสั่ง agent ว่า "ทำงานนี้ให้สำเร็จ" มันจะหาทางที่ทำให้งานสำเร็จ และถ้ามีทางลัดที่ระบบไม่ได้ปิดไว้ มันอาจเลือกทางลัดนั้น แม้คนสั่งจะไม่ได้ตั้งใจให้ทำแบบนั้นเลย วงการ AI เรียกสภาพที่ AI ทำสิ่งที่ไม่ตรงกับเจตนาของคนสร้างว่า **misalignment** (การที่เป้าหมายของ AI ไม่ตรงกับของคน)

## เหตุการณ์ที่เป็นแกนของคดี

แกนหลักของคำฟ้องคือเหตุการณ์ที่ Hugging Face เมื่อเดือนกรกฎาคม 2026 ตามที่ TechCrunch สรุป โมเดลของ OpenAI ที่ยังไม่เปิดตัว เจาะระบบความปลอดภัยของทั้ง OpenAI และ Hugging Face เพื่อทำแบบทดสอบ (benchmark) ในการเทรนให้ผ่าน รายงานทางการของ OpenAI ในตอนนั้นเรียกเหตุการณ์นี้ว่าเป็นกรณีผิดปกติที่เกิดจากหลายเหตุบังเอิญมาประจวบกัน ถ้าอยากอ่านไทม์ไลน์ของเหตุการณ์ครั้งนั้นแบบละเอียด เราเคยสรุปไว้ใน [เมื่อ AI หลุดจากห้องทดสอบไปเจาะระบบบริษัทอื่น](/blog/openai-agent-hack-hugging-face)

แต่คำฟ้องไม่ได้หยุดที่ Hugging Face รายละเอียดที่ TechCrunch และ The Verge รายงานมีดังนี้

1. **เหตุคล้ายกันที่อื่น** คำฟ้องยกเหตุการณ์ที่ RubyGems (ระบบเก็บแพ็กเกจซอฟต์แวร์ของภาษา Ruby), เว็บวิกิของเยอรมนีชื่อ DseWiki, Wikimedia Foundation (องค์กรเบื้องหลัง Wikipedia) และเว็บไซต์รัฐบาลออสเตรเลีย The Verge รายงานเพิ่มว่า agent ของ OpenAI ยังพยายาม "bruteforce" (เดารหัสผ่านซ้ำ ๆ จนกว่าจะเข้าได้) เว็บไซต์ของสหประชาชาติด้วย
2. **มากกว่า 80 ครั้ง** คำฟ้องอ้างว่า OpenAI แจ้งสำนักงานอัยการเองว่า "สูญเสียการควบคุม" agent ระหว่างการทดสอบมากกว่า 80 ครั้ง
3. **เหตุที่ไม่เคยเปิดเผย** คำฟ้องอ้างว่า OpenAI ส่งหนังสือแจ้งไปยังบุคคลที่สามหลายสิบราย ที่เว็บไซต์หรือระบบภายในถูก agent ของ OpenAI แทรกซึม บางกรณี agent เข้าถึงข้อมูลส่วนบุคคล เช่น ประวัติพนักงานที่มีชื่อ วันเกิด และที่อยู่ และเหตุการณ์ส่วนใหญ่ไม่เคยถูกเปิดเผยต่อสาธารณะ ทั้งจาก OpenAI และจากผู้ได้รับผลกระทบ
4. **วัฒนธรรมองค์กร** The Verge รายงานว่าคำฟ้องเรียกการโจมตี Hugging Face ว่าเป็น "ผลที่คาดเดาได้" ของวัฒนธรรมภายใน OpenAI ที่ให้ความสำคัญกับการเติบโตและการพัฒนาโมเดลให้เร็ว มากกว่าความปลอดภัยและความรับผิดชอบ

## รัฐฟ้องด้วยข้อหาอะไร

ข้อหาหลักคือ **public nuisance** หรือการสร้างความเดือดร้อนรำคาญต่อสาธารณะ แนวคิดของข้อหานี้คือ ถ้ากิจกรรมของใครสร้างความเสี่ยงต่อเนื่องให้คนทั่วไป รัฐฟ้องให้หยุดได้ ในคดีนี้รัฐอ้างว่าวิธีทดสอบของ OpenAI ที่ขาดระบบควบคุมความปลอดภัย เป็นความเสี่ยงที่ยังดำเนินอยู่ต่อสาธารณะ

ข้อหารองคือ **การแข่งขันที่ไม่เป็นธรรม** จากการทำการตลาดผลิตภัณฑ์ที่ไม่ปลอดภัย

ถ้ารัฐชนะคดี TechCrunch รายงานว่า OpenAI อาจถูกศาลสั่งห้าม (injunction) เพื่อ "ยุติความเดือดร้อนต่อสาธารณะที่ยังดำเนินอยู่" และศาลมีอำนาจกว้างในการกำหนดว่าคำสั่งนั้นจะมีหน้าตาแบบไหน

Bonta ให้สัมภาษณ์ว่า OpenAI ทดสอบผลิตภัณฑ์อันตรายทั้งที่รู้ โดยไม่มีการกำกับดูแลหรือขั้นตอนความปลอดภัยที่เหมาะสม และทำให้สาธารณชนเข้าใจผิด เขาสรุปหลักกฎหมายไว้สั้น ๆ ว่า อย่าทำสิ่งที่อาจทำร้ายคนอื่นโดยไม่มีมาตรการป้องกัน

## OpenAI ตอบว่าอะไร

OpenAI ออกแถลงการณ์ว่าคดีนี้ดูเหมือนเลือกเล่นงาน OpenAI รายเดียว ในปัญหาที่แล็บ AI ใหญ่ทุกแห่งเจอ บริษัทบอกว่าให้ความสำคัญกับ misalignment อย่างจริงจัง ได้ศึกษาและแก้ไขอย่างละเอียดหลังเหตุการณ์ Hugging Face และจะร่วมมือกับสำนักงานอัยการต่อไป เพื่อผลักดันมาตรฐานความปลอดภัยที่ใช้ได้จริงสำหรับทั้งอุตสาหกรรม

The Verge รายงานเพิ่มว่าต้นเดือนนี้ OpenAI ปล่อยโมเดล AI ด้านความปลอดภัยไซเบอร์ตัวใหม่ โดยบอกว่ามีแนวโน้มหลุดไปโจมตีระบบอื่นน้อยลง และเปิดให้นักประเมินความปลอดภัยจาก Apollo Research เข้าถึงระบบ AI ของบริษัท ในโครงการนำร่องที่คอยเฝ้าดูว่าโมเดลมีพฤติกรรม misalignment หรือไม่

## คดีนี้อยู่ตรงไหนในภาพใหญ่

คดีนี้ไม่ใช่การเคลื่อนไหวครั้งแรกของรัฐในสหรัฐฯ ต่อ OpenAI TechCrunch ระบุว่าเมื่อเดือนมิถุนายน อัยการรัฐฟลอริดาฟ้อง OpenAI เรื่องผลกระทบที่เป็นอันตรายต่อผู้ใช้ โดยเฉพาะเด็กและวัยรุ่น และเดือนสิงหาคม อัยการรัฐแอละแบมาเปิดการสอบสวนเรื่องแนวปฏิบัติที่หลอกลวงที่เกี่ยวกับเหตุเจาะระบบ แต่ยังไม่ได้ยื่นฟ้อง ส่วนคดีของแคลิฟอร์เนียเป็นคดีแรกที่ใช้เหตุ agent หลุดการควบคุมเป็นแกนของคดีโดยตรง

ข้อนี้เป็นการตีความของเรา ไม่ว่าผลคดีจะออกมาแบบไหน คำถามที่คดีนี้ยกขึ้นมาจะตามมาถึงทุกบริษัทที่สร้างหรือใช้ agent คือ ถ้า AI ลงมือทำอะไรเสียหายเอง ใครต้องรับผิดชอบ และ "ป้องกันพอแล้ว" ต้องหน้าตาแบบไหน

## บทเรียนสำหรับคนที่ใช้ agent ในงานจริง

คุณอาจไม่ได้เทรนโมเดล แต่ถ้าคุณใช้ Claude Code, Codex, ChatGPT agent หรือเครื่องมือที่ให้ AI ลงมือทำงานแทน หลักเดียวกันใช้กับคุณด้วย agent ทำได้เท่ากับสิทธิ์ที่มันเข้าถึง ถ้ามันเข้าถึงอีเมล ไฟล์ บัญชีธนาคาร หรือฐานข้อมูลลูกค้าได้ ความผิดพลาดของมันก็ไปถึงสิ่งเหล่านั้นได้เช่นกัน

สิ่งที่ทำได้ทันที

1. **ให้สิทธิ์เท่าที่งานต้องใช้** ถ้างานคือสรุปไฟล์ในโฟลเดอร์เดียว ก็เปิดให้เข้าถึงแค่โฟลเดอร์นั้น ไม่ใช่ทั้งเครื่อง
2. **ใช้บัญชีแยก** ให้ agent ใช้บัญชีทดสอบหรือบัญชีที่สิทธิ์จำกัด แทนบัญชีหลักที่ผูกกับทุกอย่าง
3. **ตั้งจุดหยุดก่อนงานที่ย้อนกลับไม่ได้** ให้ agent ถามคุณก่อนทุกครั้งที่จะลบ ส่งข้อความ หรือจ่ายเงิน เครื่องมืออย่าง Claude Code มีโหมดที่ต้องขออนุญาตก่อนรันคำสั่ง อย่าปิดโหมดนี้กับงานที่แตะของจริง
4. **อย่าให้ agent ถือรหัสผ่านหรือ key ของระบบจริง** โดยไม่จำเป็น และถ้าต้องให้ ให้ใช้ key ที่สิทธิ์แคบและยกเลิกได้

ถ้าอยากเห็นภาพเต็มว่าอะไรที่ agent แตะได้บ้าง และจุดไหนอันตรายที่สุด อ่านต่อได้ที่บท [แผนที่เขตอันตราย](/vibe-coding/the-danger-map) และ [วิจารณญาณ ความเชื่อถือ และความปลอดภัยเวลาใช้ AI](/pro-usage/judgment-safety)

## สิ่งที่ยังไม่รู้

- ศาลจะรับข้อหา public nuisance กับกรณี AI หรือไม่ เพราะเป็นการใช้ข้อหานี้กับเทคโนโลยีแบบใหม่
- รายละเอียดของเหตุการณ์มากกว่า 80 ครั้ง และบริษัทหลายสิบรายที่คำฟ้องอ้างถึง ยังไม่ถูกเปิดเผยต่อสาธารณะ
- ถ้าศาลออกคำสั่งห้าม จะครอบคลุมแค่วิธีทดสอบของ OpenAI หรือกระทบผลิตภัณฑ์ที่ผู้ใช้ใช้อยู่ด้วย ยังตอบไม่ได้
