คืนวันศุกร์คืนหนึ่ง Andrej Karpathy เปิด YouTube แล้วไม่อยากดูอะไรที่มันแนะนำเลย เขาเขียนไว้ในบล็อกว่าอัลกอริทึมนี้คงทำงานดีกับคนส่วนใหญ่บนอินเทอร์เน็ต แต่ไม่ได้ทำงานกับเขา แทนที่จะปิดเครื่องไปนอน เขาตัดสินใจสร้างเว็บดูวิดีโอของตัวเองขึ้นมาแทน ใช้เวลาราว 2 ชั่วโมง และไม่ได้เขียนโค้ดเองสักบรรทัด

Karpathy เป็นหนึ่งในทีมผู้ก่อตั้ง OpenAI และเคยคุมงาน AI ของรถยนต์ไร้คนขับที่ Tesla เขาคือคนที่ทำให้คำว่า vibe coding เป็นที่รู้จัก บทความนี้สรุปจากบล็อกของเขาเองชื่อ "HackerTube" ที่เผยแพร่วันที่ 31 ตุลาคม 2026 ตัวเลขทุกตัวมาจากบล็อกนั้น ส่วนที่เป็นการตีความของเรา เราจะเขียนบอกไว้ชัด ๆ

## HackerTube คืออะไร

แนวคิดง่ายมาก Hacker News เป็นเว็บบอร์ดของคนสายเทคและสตาร์ทอัพ คนในนั้นชอบแปะลิงก์ YouTube ในคอมเมนต์พร้อมบอกว่า "คลิปนี้ดีมาก ต้องดู" มาเป็นสิบกว่าปี Karpathy เลยคิดว่า ถ้าเอาคลิปทั้งหมดที่คนกลุ่มนี้แนะนำมารวมเป็นเว็บเดียว ก็จะได้ YouTube ที่คัดโดยคน ไม่ใช่โดยอัลกอริทึมที่อยากให้คุณดูนานที่สุด

ผลลัพธ์ที่ hackertube.org มีคลิป 6,454 คลิป แบ่งเป็น 150 หัวข้อ เป็นคลิปที่ถูกแนะนำตั้งแต่ปี 2007 ถึง 2026 และมีลูกเล่นที่เขาเลือกใส่เอง เช่น

- **ใช้ภาพจากกลางคลิปเป็นภาพปก** แทนภาพปกที่เจ้าของคลิปตั้งไว้ ซึ่งมักทำมาให้คนอยากกดมากกว่าบอกว่าในคลิปมีอะไร
- **ระบบแนะนำ "For You" ที่ไม่ต้องมีบัญชี** ข้อมูลว่าคุณชอบอะไรเก็บไว้ในเบราว์เซอร์ของคุณเองระหว่างใช้งาน ไม่ได้ส่งไปเก็บที่ไหน
- **ปุ่มลัดบนคีย์บอร์ด**
- **ดาวน์โหลดข้อมูลทั้งเว็บได้** เพื่อให้คนอื่นเอาไปให้ AI agent ของตัวเองสร้างเวอร์ชันของตัวเองต่อ

## สร้างขึ้นมาได้ยังไง ทีละขั้น

นี่คือส่วนที่น่าเรียนที่สุด เพราะ Karpathy เล่าลำดับงานไว้ค่อนข้างละเอียด เครื่องมือหลักคือ Claude Code แอปบน Mac ใช้ model ตัวใหญ่ Opus 5.5 เป็นตัวหลัก และใช้ Sonnet ซึ่งเป็นรุ่นกลางในงานบางช่วง

**ขั้นที่ 1 หาวัตถุดิบ** มีคนทำชุดข้อมูลคอมเมนต์ทั้งหมดของ Hacker News ไว้บน Hugging Face (เว็บที่คนในวงการ AI ใช้แชร์ model และชุดข้อมูล) Opus ดาวน์โหลดมาแล้วกรองรอบแรก เอาเฉพาะคอมเมนต์ที่มีลิงก์ YouTube

**ขั้นที่ 2 คัดของจริง** คอมเมนต์ที่มีลิงก์ไม่ได้แปลว่าเป็นการแนะนำเสมอไป บางอันเป็นสแปม บางอันแปะลิงก์เพื่อด่า ขั้นนี้เขาให้ Sonnet ทำงานผ่านระบบ Workflow ของ Claude Code ซึ่งเป็นการแตกงานเป็นชิ้นเล็กแล้วให้ตัวช่วยย่อยหลายตัวทำพร้อมกัน ผลคือเหลือราว 4 หมื่นคอมเมนต์ที่แนะนำคลิปจริง ๆ

**ขั้นที่ 3 ทำหน้าเว็บ** เอาผลทั้งหมดมาครอบด้วยหน้าตาแบบ YouTube

**ขั้นที่ 4 ขึ้นเว็บจริง** Karpathy เปิดเซิร์ฟเวอร์เช่า (ในวงการเรียกว่า VPS คือคอมพิวเตอร์ที่เช่าไว้บนอินเทอร์เน็ต เปิดอยู่ตลอด 24 ชั่วโมง) แล้วส่งเลข IP ของเครื่องให้ Claude พร้อมสั่งว่าให้ "อัปเดต deploy ปิดช่องโหว่ เสริมความแข็งแรง และปรับให้เร็ว" ที่เหลือ Claude จัดการเอง

ทั้งหมดใช้เวลาราว 2 ชั่วโมง และเขาบอกว่าไม่ได้นั่งเฝ้าตลอด ทำอย่างอื่นสลับไปในระหว่างที่ Claude ทำงาน

## สามอย่างที่ยังต้องเป็นคน

Karpathy ระบุว่าสิ่งที่เขาต้องทำด้วยมือตัวเองมีแค่สามอย่าง

1. สร้างกุญแจ API ของ Google Cloud เพื่อให้เว็บดึงข้อมูลคลิปจาก YouTube ได้ (ชื่อคลิป ความยาว ฯลฯ)
2. เปิดเซิร์ฟเวอร์
3. ซื้อโดเมน

ถ้าสังเกตดี ทั้งสามอย่างมีจุดร่วมกัน คือเป็นเรื่อง **ตัวตนและเงิน** ต้องล็อกอินบัญชีของตัวเอง ต้องผูกบัตร ต้องยอมรับเงื่อนไขในนามตัวเอง นี่คือเส้นที่ AI agent วันนี้ยังไม่ข้ามและไม่ควรข้าม (ส่วนนี้เป็นการตีความของเรา) ถ้าคุณกำลังวางแผนสร้างอะไรสักอย่างด้วย AI ให้แยกงานแบบนี้ออกมาก่อนเลย มันคือรายการงานที่คุณต้องเตรียมเอง ส่วนที่เหลือคือสิ่งที่ส่งต่อให้ AI ได้

## ทำไมใช้ model สองขนาด

ในบล็อกไม่ได้อธิบายเหตุผลว่าทำไมให้ Sonnet ทำขั้นที่ 2 แทน Opus ส่วนนี้เป็นการอธิบายของเราจากหลักการทั่วไป

งานคัดคอมเมนต์เป็นงานที่ **ง่ายแต่เยอะ** แต่ละชิ้นแค่ต้องตัดสินว่า "คอมเมนต์นี้แนะนำคลิปจริงไหม" ไม่ต้องคิดลึก แต่มีเป็นหมื่นชิ้น ถ้าใช้ model ตัวใหญ่ทำทุกชิ้นจะทั้งช้าและแพงโดยไม่จำเป็น model ตัวกลางทำงานแบบนี้ได้ดีพอ เร็วกว่า และถูกกว่า ส่วนงานที่ต้องคิดวางโครงสร้าง ตัดสินใจหลายชั้น อย่างการเขียนโค้ดทั้งเว็บหรือการตั้งค่าเซิร์ฟเวอร์ ถึงค่อยใช้ตัวใหญ่

หลักนี้ใช้กับงานของคุณได้ตรง ๆ เวลาให้ AI ประมวลผลข้อมูลเป็นกอง เช่นจัดหมวดรีวิวลูกค้า 5,000 รายการ ไม่จำเป็นต้องใช้ model ที่เก่งที่สุดเสมอ

## บทเรียนที่ไม่ได้อยู่ในหัวข้อข่าว

ประโยคที่คนแชร์กันมากที่สุดคือที่ Karpathy บอกว่าเขาไม่ได้ทำงานวิศวกรรมแบบดั้งเดิมอีกแล้ว แค่คุยกับ Claude แล้วให้มันทำทุกอย่าง ฟังแล้วเหมือนใครก็ทำได้ ซึ่งจริงครึ่งเดียว

สิ่งที่ Karpathy ไม่ต้องทำคือ **พิมพ์โค้ด** แต่สิ่งที่เขายังทำอยู่เต็ม ๆ คือ

- **รู้ว่าอยากได้อะไร** เขามีภาพชัดตั้งแต่ต้นว่าเว็บนี้ต่างจาก YouTube ตรงไหน (คัดโดยคน ภาพปกจากกลางคลิป ไม่ต้องมีบัญชี)
- **รู้ว่าข้อมูลอยู่ที่ไหน** เขารู้ว่ามีชุดข้อมูล Hacker News อยู่แล้ว ไม่ต้องไปดูดเว็บเอง
- **แบ่งงานเป็นขั้น** หาวัตถุดิบ คัด ทำหน้าตา ขึ้นเว็บ แต่ละขั้นตรวจผลได้
- **รู้ว่าต้องสั่งตรวจอะไร** คำว่า "ปิดช่องโหว่และเสริมความแข็งแรง" คือคำสั่งที่มือใหม่มักลืม เพราะเว็บที่ใช้งานได้กับเว็บที่ปลอดภัยเป็นคนละเรื่องกัน AI ไม่ได้ทำให้เองทุกครั้งถ้าคุณไม่สั่ง

พูดอีกแบบคือ งานเปลี่ยนจากการเป็นคนเขียน มาเป็นคนกำหนดโจทย์และคนตรวจงาน ซึ่งเป็นทักษะที่คนทำงานออฟฟิศและเจ้าของธุรกิจมีอยู่แล้วไม่น้อย Karpathy ปิดบล็อกด้วยการบอกว่ามันยังรู้สึกเหมือนทำงานเป็นทีมอยู่ดี

## ถ้าอยากลองแบบนี้บ้าง

- **เริ่มจากปัญหาของตัวเอง** Karpathy ไม่ได้สร้างเว็บเพื่อขาย เขาสร้างเพราะรำคาญอะไรบางอย่างในชีวิตตัวเอง โปรเจกต์แรกที่ดีที่สุดมักมาจากตรงนี้
- **ใช้เครื่องมือที่รันคำสั่งได้จริง** งานแบบนี้ทำในหน้าแชท ChatGPT หรือ Claude บนเว็บไม่ได้ เพราะต้องดาวน์โหลดไฟล์ รันโปรแกรม และเข้าเซิร์ฟเวอร์ ต้องใช้ AI agent อย่าง Claude Code, Cowork หรือ Codex
- **เตรียมงานส่วนที่เป็นของคุณไว้ก่อน** บัญชี กุญแจ API โดเมน เซิร์ฟเวอร์ คืองานที่คุณต้องทำเอง และอย่าวางกุญแจ API ไว้ในที่ที่คนอื่นเห็นได้
- **สั่งให้ตรวจความปลอดภัยทุกครั้งก่อนเปิดให้คนอื่นใช้** อย่าคิดว่า AI ทำให้เองแล้ว

ถ้าอยากเข้าใจพื้นฐานการสร้างแอปด้วย AI ตั้งแต่ต้น ตั้งแต่ terminal ไปจนถึงการ deploy ขึ้นเว็บจริง อ่านต่อได้ในหมวด [Vibe Coding](/vibe-coding) ของเรา
